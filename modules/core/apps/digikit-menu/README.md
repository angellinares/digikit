# core/digikit-menu

Adds **SETTINGS > DIGIKIT** (the ninth row, after SYSTEM). Written in C on `<dk/ui.h>` (`sdk/include/dk/ui.h`); `core/ui` draws it with the firmware's own views. Emulator only: nothing here has run on a device.

The DIGIKIT menu has the rows ABOUT, HEALTH, MEMORY, and MODULES (a safe-mode row `SAFE: <reason>` comes first in safe mode). There is no DEBUG row: the debug log is on while `digikit/debug` is loaded. The check mark of a MODULES row is the only on/off of a module (there is no REMOTE switch).

- **MODULES** is a list (`DK_UI_LIST`) with one row per `.dkm` file of the +Drive module store (`digikit/modules/` of the `plus_drive/` folder, [docs/design/digikit-store.md](../../../../docs/design/digikit-store.md)), up to 32. A row reads `NAME KIND SIZE`: the file name without `.dkm` (12 characters; a longer name keeps its start and its end around a `~`), the kind (`FX` when the module has effects, `MACH` when it has machines, else `TOOL`) and the memory the module takes in the arena and the DSP area (`<1K`, `259K`, `1.2M`), right aligned. The needs come from `dkrt_scan`; the kind and the size are blank (`----`, the file size) for a file without readable needs. With no file the list says `NO MODULES ON CARD` (`NO STORE`, `STORE READ ERROR` or `BAD STORE` when the store cannot be read).
  - **The check mark** means "load at the next restart". It starts from the saved selection (`dkrt_selection_get`). YES toggles it. Checking a module that does not fit next to the checked ones (the runtime's fit rule, `dkrt_fit`: the checked modules load into an empty runtime, in list order) or that this runtime or device cannot load is refused: the mark goes back off and a confirm opens with the title `<NAME> DOES NOT FIT` (text: the first short resource, for example `DSP 400K > 254K FREE`) or `<NAME> NOT COMPATIBLE`. A toast would be hidden while a menu is open.
  - **RIGHT** opens the side panel of the row: `LOAD` or `UNLOAD` (the same as YES, with the same refusals), `ROUTE...` (only for a loaded module with an effect that has a page of its own), `SETTINGS...` (only for a loaded module that exports `dkm_menu`) and `INFO`. ROUTE... opens a choice `ROUTE` with SEND and MASTER, limited to the routes the effect allows (its manifest's `routes`) and, for SEND, to the free send slots (CAPACITY `SEND_SLOTS`, counted over the pending routes). A module's effects share one route setting. INFO is a text page: name, version (from the file's header), size, DSP and CPU share of the module alone (`dkrt_fit` with only that module checked), whether it fits next to the checked ones, its status (loaded, loading, not loaded), what the restart will do with it and its route.
  - **NO** goes back. With changes pending (a row checked or unchecked, an effect with another route; also in safe mode, where a restart is the way out) the list stays and opens a confirm `APPLY & RESTART?` with the number of changes. YES saves the selection (`dkrt_selection_set`) and the changed routes (`dkrt_settings_put` of `fx/route/<module id>`, one byte, 1 send, 0 master), writes the settings to the card at once (`dkrt_settings_flush`) and restarts (`dkrt_restart`); a refusal is shown in a confirm (`NOT SAVED`, `NO RESTART`). NO drops the pending changes and closes the list. Modules are loaded by the runtime at boot, not by the menu. The route takes effect at the restart (the FX key's pages are fixed when the main view is built).
- **SETTINGS...** opens the module's own menu, titled with the module's name without its author. The menu is built the first time the user opens it and kept (one per loaded module, up to 16); each open calls the module's `dkm_menu` (address in `DkrtModule.menu`) to fill it. The module adds its rows with `<dk/ui.h>`; the lifetime rule is in docs/ARCHITECTURE.md.
- **HEALTH** shows CPU load, the DSP's block time (average and maximum of the last second), the free firmware heap and its largest block, the free CPU memory (the runtime arena), the free DSP area and the store, and refreshes itself about twice a second without a key press (the page registers a function with `dkrt_poll_set`, which the UI loop calls once per pass; it stops when the page is closed). The figures need `core/health`; without it the page says so. Finding 41.
- **MEMORY** shows the runtime's capacity (the CAPACITY command's entries, `dkrt_capacity`) as text rows with a ten-character bar: `DSP` and `CPU` (the arena) as a percent, `MODS`, `MACH`, `VOICE`, `PARAM` and `PAGE` as used/limit. Finding 57.
- **ABOUT** shows the version, the runtime's ABI, the card state, safe mode and why, this boot's modules with each result text, and the free arena in KB.

ABOUT, HEALTH, MEMORY and INFO are text pages (`DK_UI_TEXT_PAGE`: no highlighted row, the keys scroll; a text page opens at its first row). The SETTINGS row keeps the icon of its neighbours (`dk_ui_stock_row`, `modules/core/adapters/ui/include/dk_ui_core.h`). In safe mode a confirm names the reason when DIGIKIT opens for the first time.

Firmware: DT2 1.17 and DN2 1.12 (the same sites and helpers, found by function hash).

## The interface to the runtime

The module `requires` `core/runtime` and `core/ui`. The runtime's exported C functions (`modules/core/runtime/include/dkrt.h`, written by `patchkit gen` from `modules/core/runtime/abi.toml`) are undefined symbols that patchkit links: `dkrt_scan`, `dkrt_scan_reads` and `dkrt_fit` (the store and what fits), `dkrt_selection_get` and `_set`, `dkrt_restart`, `dkrt_settings_put` and `_flush`, `dkrt_boot_info`, `dkrt_status`, `dkrt_module` and `dkrt_fx` (the loaded modules and their effects), `dkrt_capacity`, `dkrt_health`, `dkrt_blocks`, `dkrt_poll_set`, `dkrt_diag`, `dkrt_debug_set` and `dkrt_module_header` (INFO's version). The UI calls are `dk_ui_*` of `core/ui`.

## Notes

- No hook and no firmware include (an app, `layercheck` enforces it): `core/ui` owns the hook at the end of the SETTINGS item list rebuild and calls the menu's `dk_app_settings_rows`, which adds the DIGIKIT row. Everything else is `<dk/ui.h>`; the firmware's menu classes (finding 28, 71) are `core/ui`'s concern.
- Memory: the scan table (32 entries), the fit result and the pending state are statics of the module. The card read of INFO is done by the runtime (`dkrt_module_header`, in its own DMA-safe buffer); module RAM is written by this code only (the proofs check stray writes). The module links without `memcpy` and `memset`.
- Globals read by the proofs by name (layout: 24-byte text rows): `STORE`, `NENT`, `NOK`, `LOADED`, `TICK` (the checked rows), `DK_LOAD`/`DK_LOAD_N` (the rows of MODULES), `DK_PANEL`/`DK_PANEL_N` (the side panel), `DK_ROUTE_N`/`DK_ROUTE_ITEM` (the routes the last choice offered), `DK_FXR_PEND` (pending routes), `DK_ABOUT`/`DK_ABOUT_N`, `DK_MEM`/`DK_MEM_N`, `DK_LINES`, `DK_HEALTH`, `DK_HEALTH_MENU`, `DK_REDRAWS`, `DK_POLLS`, `dk_poll`, `DK_POPUP`, `DK_POPUP_TEXT` and `DK_POPUPS` (the last confirm), `DK_PENDING`, `DK_APPLIES`, `DK_APPLY_SET`, `DK_APPLY_RESTART`, `DK_FXR_SET`, `DK_FXR_FLUSH`, `DK_NEEDS_READS` and `dk_entry_count`.
