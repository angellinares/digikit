# Digitakt II / Digitone II — findings

Current targets are **Digitakt II OS 1.16** and **Digitone II OS 1.11**. Older
sections were written against DT2 1.15C and are kept for their history; where a
later section corrects one, it is marked **[C]**.

This file is the entry point into the lab notes for the Digitakt II / Digitone
II reverse-engineering work; the notes themselves live in `docs/findings/`,
one file per topic, in the chronological order they were written (later
sections often correct earlier ones — read a file top to bottom). Start with
the topic closest to what you're doing, or grep across all of them with
`rg . docs/findings/`.

Evidence classes used below:
**[V]** verified by running it here · **[D]** documented by prior research, not
re-checked · **[O]** open / nobody has established this · **[C]** corrects an
earlier claim.

## Contents

Current SHARC follow-up: [native DT2 stock versus runtime diagnosis](findings/68-sharc-runtime-performance.md)
(**[D] [C]**, 2026-10-26): patched parameter-conversion code remains a major
interpreter workload; stock sampling is mostly compiled work. The two-core PGO profile
cuts DSP-thread CPU by about 18% on both devices; the DT2 root change saves 9-12% on the patched runtime (2026-11-01).

Runtime test follow-up: [phase timing and bounded DT2 pilot](findings/69-runtime-test-timing.md)
(**[D] [C]**, 2026-10-27): startup, settling, restarts and scenario work are now
measured separately; no waits or test isolation were changed.

Host test cache pilot: [Nx cache isolation and input probes](findings/nx-pilot.md)
(**[D] [O]**, 2026-11-01): local host repeat/unrelated-change hits, intentional-failure miss and
restored-input hit observed; named Rust execution passed ten tests and runtime service commands passed
both device cases. Host preflight uses Nx affected selection; five host groups passed cache probes,
with one bounded support/session timing pair. Rust/runtime cache audits and merge-gate setup remain open.
